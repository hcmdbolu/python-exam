1.1 Binary Units & Data Storage Capacities
📌 Mock Checklist: Binary unit🎯 Year 10 Deep Dive
🧠 Real-World Analogy: Why Computers Speak Binary
Imagine trying to communicate across a noisy football stadium using a flashlight. If you tried to use 10 different brightness levels (0 to 9) to represent numbers, the person across the pitch wouldn't be able to tell the difference between "level 6" and "level 7" through the fog. Instead, you simply use ON (1) and OFF (0).

Inside a computer's CPU and memory chips are billions of microscopic semiconductor switches called transistors. Electricity is either flowing (High Voltage = 1) or blocked (Low Voltage = 0). Because two states are unmistakable even with tiny voltage fluctuations, binary makes computers fast and reliable.

1. The Building Blocks of Data

  • Bit (b): Short for Binary Digit. It is the smallest atomic piece of data in computing—a single 0 or 1.
  • Nibble: A group of 4 bits (half a byte). Why does a nibble exist? Because $2^4 = 16$ possible combinations (`0000` to `1111`), which maps 1-to-1 with a single Hexadecimal digit!
  • Byte (B): A group of 8 bits. Historically, 1 byte was the standard size needed to store a single keyboard character in ASCII (e.g., 'A' = 01000001₂).
Figure 1.1: Anatomy of a Byte — MSB (Most Significant Bit) is on the far left (128); LSB (Least Significant Bit) is on the far right (1).

2. Storage Capacity Scale: GCSE Standard vs. True Binary

In GCSE Computer Science exams (OCR, AQA, Edexcel), storage capacity questions use clean powers of 1,000 so you can calculate without a calculator. However, operating systems and RAM manufacturers often use powers of 1,024 ($2^{10}$):

Internet broadband speeds are advertised in Megabits per second (Mbps), whereas file sizes are measured in Megabytes (MB).
Worked Example: How long does it take to download a 50 MB file on a 100 Mbps connection?
1. Convert file size to bits: $50\text{ MB} \times 8 = 400\text{ Megabits (Mb)}$.
2. Divide by speed: $400\text{ Mb} \div 100\text{ Mbps} = \mathbf{4\text{ seconds}}$.
1.2 Binary, Denary & Hexadecimal Conversions
📌 Mock Checklist: Binary/denary/hex conversion🏷️ Paper 1: Number Systems

1. Why Do Computer Scientists Use Hexadecimal (Base 16)?

First, clear up the biggest myth: Computers do NOT understand Hexadecimal! Inside the hardware, everything is still 100% binary (`1`s and `0`s). Hexadecimal is purely a human-friendly shorthand for binary.

  • Why Base 16? Because $16 = 2^4$, one single Hex character represents 4 binary bits (1 nibble). Therefore, an entire 8-bit byte can be written in just 2 Hex digits!
  • Where is it used? MAC addresses (`A4:83:E7:2B:19:0C`), IPv6 addresses, HTML/CSS color codes (`#FF5733`), and CPU memory error dumps.
  • Exam Mark Scheme Answer (2 Marks): (1) Much shorter/more compact to display on screen than long binary strings; (2) Far less prone to human transcription errors when reading or typing.

2. Step-by-Step Conversion Methods

Method A: 8-Bit Binary → Denary

Write the powers of 2 from right ($2^0 = 1$) to left ($2^7 = 128$). Add every column containing a 1. Example: 10101100₂

128 ($2^7$)64 ($2^6$)32 ($2^5$)16 ($2^4$)8 ($2^3$)4 ($2^2$)2 ($2^1$)1 ($2^0$)
10101100
128—32—84——

Total: $128 + 32 + 8 + 4 = \mathbf{172_{10}}$.

Method B: Denary → 8-Bit Binary (Greedy Subtraction)

To convert $213_{10}$ to binary: ask left-to-right if each column fits into the remaining total:

  • Does 128 fit into 213? Yes (1) → Remainder: $213 - 128 = 85$
  • Does 64 fit into 85? Yes (1) → Remainder: $85 - 64 = 21$
  • Does 32 fit into 21? No (0) → Remainder: $21$
  • Does 16 fit into 21? Yes (1) → Remainder: $21 - 16 = 5$
  • Does 8 fit into 5? No (0) → Remainder: $5$
  • Does 4 fit into 5? Yes (1) → Remainder: $5 - 4 = 1$
  • Does 2 fit into 1? No (0) → Remainder: $1$
  • Does 1 fit into 1? Yes (1) → Remainder: $0$
  • Result: 11010101₂

Method C: Binary ↔ Hexadecimal (The Nibble Split)

⚡ Remember: 0–9 stay digits; 10=A, 11=B, 12=C, 13=D, 14=E, 15=F
Convert 11011011₂ to Hexadecimal:
1. Split the byte in half into two 4-bit nibbles: 1101 | 1011
2. Value each nibble using 8 - 4 - 2 - 1:
   • Left nibble: $8 + 4 + 0 + 1 = 13 \rightarrow \mathbf{D}$
   • Right nibble: $8 + 0 + 2 + 1 = 11 \rightarrow \mathbf{B}$
3. Result: DB₁₆. (To convert Hex back to Binary, simply expand each Hex digit into its 4-bit nibble!)

1.3 Binary Arithmetic, Overflow & Logical Shifts
📌 Mock Checklist: Binary arithmetic🏷️ Paper 1: Data Representation

1. Column Binary Addition

Just like denary addition carries when a column reaches 10, binary addition carries whenever a column reaches 2 (which is 10₂):

1 + 101$2_{10} = 10_2$ (0 in units, 1 in twos)

🚨 Overflow Error (What Happens When a Result Exceeds 255?)
An 8-bit CPU register can only hold values from 00000000₂ (0) to 11111111₂ (255). If adding two 8-bit numbers produces a carry out of the 8th (leftmost) column, a 9th bit is generated. Because the register only has 8 slots, the 9th bit is dropped—causing an Overflow Error and an inaccurate result (e.g., $200 + 100 = 300$, which overflows to $44$ in 8 bits!).

2. Logical Binary Shifts (Fast Hardware Math)

Inside a CPU, shifting bits left or right is much faster than running full multiplication or division circuits:

  • Logical Left Shift: Every bit moves n places to the left; empty slots on the right are padded with 0s.
    • Shift Left by 1 = Multiply by 2 ($\times 2^1$)
    • Shift Left by 2 = Multiply by 4 ($\times 2^2$)
    • Shift Left by 3 = Multiply by 8 ($\times 2^3$)
    • Warning: If a 1 is pushed off the left edge, an overflow error occurs.
  • Logical Right Shift: Every bit moves n places to the right; empty slots on the left are padded with 0s.
    • Shift Right by 1 = Divide by 2 ($\div 2^1$)
    • Shift Right by 2 = Divide by 4 ($\div 2^2$)
    • Warning: Any 1 pushed off the right edge is lost, causing a loss of precision (e.g., $15 \div 2 = 7.5$, but binary right shift gives $7$).

2.2 Encryption & Essential Network Protocols
📌 Mock Checklist: Encryption, protocols🏷️ Paper 1: Network Security

1. How Encryption Protects Data in Transit

When you send data over public Wi-Fi, anyone with a packet sniffer can intercept the radio waves. Encryption uses a mathematical algorithm and a secret Key to scramble readable Plaintext into unreadable Ciphertext. Without the key, intercepted packets look like random garbage.

  • Symmetric Encryption: Both sender and receiver use the exact same key to lock (encrypt) and unlock (decrypt) the message. Very fast, but risky if the key is intercepted while being shared.
  • Asymmetric Encryption: Uses a mathematically linked pair of keys:
    • Public Key: Shared openly with the world—anyone can use it to encrypt a message for you.
    • Private Key: Kept strictly secret on your device—only your Private Key can decrypt messages locked with your Public Key. This powers HTTPS!

3.1 System Architecture: Von Neumann, Registers & FDE Cycle
📌 Mock Checklist: System architecture🏷️ Paper 1: Computer Systems

Proposed by mathematician John von Neumann in 1945, the Von Neumann Architecture states that both program instructions and data are stored together in the same main memory (RAM).

Figure 3.1: Von Neumann CPU Registers, ALU, CU, and System Buses connected to RAM.

1. The Four Essential CPU Registers

RegisterFull NameExact Exam Role
PCProgram CounterHolds the memory address of the next instruction to be fetched. Increments by 1 after each fetch.
MARMemory Address RegisterHolds the RAM address currently being read from or written to (sent along the unidirectional Address Bus).
MDRMemory Data RegisterHolds the actual instruction or data fetched from RAM (or waiting to be written to RAM via the bidirectional Data Bus).
ACCAccumulatorTemporarily stores intermediate and final results of calculations performed by the ALU.

2. Step-by-Step Fetch–Decode–Execute (FDE) Cycle

  1. Fetch: The address in the PC is copied into the MAR. The CPU sends a read signal along the Control Bus and the address along the Address Bus to RAM. The instruction at that address travels back along the Data Bus into the MDR. The PC increments by 1 so it points to the next instruction.
  2. Decode: The Control Unit (CU) inspects the binary opcode in the MDR to decode what operation is required.
  3. Execute: The instruction is carried out (e.g., loading a value from RAM, adding two numbers in the ALU, and storing the result in the ACC).

3. Three Factors Affecting CPU Performance

FactorHow It Works & Exam Explanation
Clock Speed (GHz)Number of FDE cycles executed per second ($3.6\text{ GHz} = 3.6\text{ billion cycles/sec}$). A higher clock speed means more instructions are processed every second.
Cache Size (MB)Ultra-fast SRAM memory built directly onto the CPU chip (`L1`, `L2`, `L3`). A larger cache stores more frequently used instructions/data close to the CPU, reducing slow trips to main RAM.
Number of CoresIndependent processing units inside one CPU chip (Dual, Quad, Octa-core). Allows true parallel execution of multiple instructions simultaneously (provided the software supports multi-threading).

3. Utility System Software

  • Encryption Software: Scrambles sensitive files on disk using a key so unauthorized users cannot read them if a laptop or USB drive is stolen.
  • Defragmentation Software: Over time, saving and deleting files on a magnetic HDD splits files into scattered fragments across the disk. Defragmentation reorganizes file blocks so they sit contiguously together, reducing read/write head movement and speeding up file loading. (Exam Trap: Never defragment an SSD—SSDs have no moving read/write heads and extra writes shorten flash lifespan!)
  • Data Compression Software: Reduces file sizes for storage and faster network transmission:
    • Lossy Compression: Permanently removes redundant data that humans barely notice (`JPEG`, `MP3`) → huge file size reduction, slight permanent quality loss.
    • Lossless Compression: Re-encodes repeating patterns without losing a single bit (`ZIP`, `PNG`, `FLAC`) → exact original file can be 100% reconstructed.
4.1 Bitmap Images, Embedded Systems & ASCII / Unicode
📌 Mock Checklist: Image, embedded system, ASCII🏷️ Paper 1: Systems & Data

1. Bitmap Images & File Size Calculations

  • Pixel (Picture Element): The smallest addressable single block of color in a bitmap grid.
  • Resolution: Dimensions of the image in pixels (Width × Height). Higher resolution increases image sharpness and file size.
  • Color Depth: Number of bits used to store the color of each pixel. A color depth of $n$ bits allows $2^n$ distinct colors (e.g., 1-bit $= 2$ colors; 8-bit $= 256$ colors; 24-bit True Color $= 16.7\text{ million}$ colors).
  • Metadata: Extra information stored inside the file header so software knows how to render it (width, height, color depth, camera model, GPS coordinates, date taken).
📐 Essential Image File Size Formula & Worked Example
Image File Size (bits) = Width (px) × Height (px) × Color Depth (bits)
Worked Example: Calculate the file size in Kilobytes (KB) of a $1000 \times 500$ pixel image with a 16-bit color depth:
1. Total bits = $1000 \times 500 \times 16 = 8,000,000\text{ bits}$
2. Convert to Bytes ($\div 8$): $8,000,000 \div 8 = 1,000,000\text{ Bytes}$
3. Convert to KB ($\div 1,000$): $1,000,000 \div 1,000 = \mathbf{1,000\text{ KB}}$ (or $1\text{ MB}$).

2. Embedded Systems

An embedded system is a dedicated computer system built into a larger mechanical or electrical appliance to perform one specific control function (often in real time).

  • Examples: Washing machine cycle controller, microwave timer, car engine management unit (ECU), traffic light controller, smart thermostat, cardiac pacemaker.
  • Characteristics: Firmware stored in ROM (not meant to be reprogrammed by the user), low power consumption, compact physical footprint, cheap to mass-produce, and ultra-reliable.

3. Character Sets: ASCII vs. Unicode

  • Character Set: A defined lookup table mapping every character to a unique binary code.
  • ASCII: Standard ASCII uses 7 bits ($2^7 = 128$ characters; Extended ASCII uses **8 bits** $= 256$ characters) covering English letters, digits, punctuation, and control codes.
  • Unicode: Uses 16 or 32 bits per character to support all global languages (Arabic, Mandarin, Yoruba, Cyrillic) and emojis—at the cost of larger text file sizes.
4.2 Mastering the GCSE 8-Marker Extended Question
📌 Mock Checklist: 8 marker question🏷️ Paper 1: Legal, Ethical, Cultural & Environmental
🎯 The PEEL + Stakeholder Strategy (How to Score 7–8 Marks)
Examiners grade 8-mark questions using Levels of Response, not simple fact-counting. To reach the top band:
1. Cover at least 3 distinct perspectives: Legal (Data Protection Act 2018 / UK GDPR, Computer Misuse Act 1990, Copyright), Environmental (e-waste toxicity, rare-earth mining, data center power), Ethical / Privacy / Cultural (surveillance, algorithmic bias, digital divide).
2. Write every paragraph using PEEL: Point → Explain why → Example tied directly to the exam scenario → Link back to the prompt.
3. Always include both benefits and drawbacks plus a concise concluding judgment.

Full Model 8-Mark Answer (Study This Structure!)

Question: "A secondary school introduces facial recognition cameras at the canteen to replace RFID smartcards. Discuss the legal, ethical, and privacy issues associated with this technology." [8 marks]

  • Legal Issues (UK GDPR / Data Protection Act 2018): Facial recognition scans constitute special category biometric personal data. Under the Data Protection Act 2018, the school must obtain explicit consent from parents/students, process data lawfully, store templates securely using strong encryption, and delete records once students leave the school.
  • Privacy & Security Risks: Centralizing biometric databases creates a high-value target for cybercriminals. Unlike a lost RFID smartcard—which can simply be deactivated and replaced—a student's facial biometric data cannot be changed if leaked in a breach.
  • Ethical & Cultural Concerns: Constant camera scanning can foster a culture of surveillance and distrust among students. Additionally, facial recognition algorithms have historically exhibited higher false-rejection rates for darker skin tones, risking unfair delays and embarrassment in the lunch queue.
  • Conclusion: Although facial recognition speeds up canteen queues and eliminates forgotten cards, the school must provide an opt-out RFID alternative, encrypt all biometric templates, and comply strictly with UK GDPR to mitigate the severe privacy risks.
5.1 Computational Thinking, Decomposition & Structure Diagrams
📌 Mock Checklist: Computational thinking, decomposition/structure diagram🏷️ Paper 2

Computational Thinking is the process of formulating a real-world problem so that a computer can solve it efficiently. It rests on three pillars:

  • Abstraction: Filtering out unnecessary detail to focus purely on the essential information needed to solve a problem. Example: The London Underground map strips away exact geographic distances, street names, and river curves so passengers can clearly see station connections.
  • Decomposition: Breaking a large, complex problem down into smaller, manageable sub-problems. Each sub-problem can then be assigned to different programmers, coded as a standalone subroutine (procedure/function), and tested independently.
  • Algorithmic Thinking: Designing a clear, logical, step-by-step sequence of instructions to solve each sub-problem.

2. Finding & Fixing Errors: Syntax vs. Logic Errors

  • Syntax Error: Occurs when code breaks the grammatical rules of the programming language (e.g., forgetting a colon : after an IF statement, missing a closing bracket, or misspelling PRINT as PRNT). The compiler/interpreter refuses to run the program until fixed.
  • Logic Error: The program runs from start to finish without crashing, but produces the wrong output due to flawed reasoning.
    • Examples: Using < instead of <= in a boundary check, adding instead of multiplying, or placing a line inside a loop when it should be outside.

3. High-Level vs. Low-Level Languages, Translators & IDEs

  • High-Level Languages (`Python`, `Java`, `C#`): Close to human English, portable across different CPU types, faster to write and maintain, but must be translated into machine code before execution.
  • Low-Level Languages:
    • Machine Code: Pure binary (`1`s and `0`s) executed directly by the CPU without translation.
    • Assembly Language: Uses short mnemonics (`LDA`, `ADD`, `STO`) with a 1-to-1 correspondence to machine code; used for device drivers and real-time embedded hardware.
  • Compilers vs. Interpreters:
    • Compiler: Translates the entire source code file at once into a standalone executable file. Runs very fast once compiled and lists all syntax errors together at the end.
    • Interpreter: Translates and executes code one line at a time. Stops immediately at the first error encountered—ideal during active coding and debugging.
  • IDE (Integrated Development Environment) Tools:
    • Code Editor: Line numbering, syntax highlighting (color-coding keywords/strings), auto-indentation, auto-complete.
    • Error Diagnostics: Highlights syntax errors and reports exact line numbers.
    • Run-Time Debugging: Breakpoints (pause execution at a chosen line), Stepping (execute one line at a time), and Variable Watch Windows (inspect variable values live).

7.1 Programming Constructs & Logic Gates
📌 Mock Checklist: Programming constructs, Logic gates🏷️ Paper 2: Logic & Flow

1. The Three Core Programming Constructs

  • Sequence: Executing statements strictly one after another in top-to-bottom order.
  • Selection: Decision branching based on boolean conditions using IF / ELIF / ELSE or SWITCH / CASE.
  • Iteration: Repeating blocks of code:

  • Essential Operators:
    • Arithmetic: +, -, *, /, MOD (remainder after division, e.g., 14 MOD 4 = 2), DIV (whole-number quotient, e.g., 14 DIV 4 = 3).

📌 Mock Checklist: Coding tasks, subroutine, file handling, SQL, input validation, array🏷️ Paper 2

1. Arrays (1D & 2D Data Structures)

An Array is a static, fixed-size data structure that stores multiple elements of the same data type under a single identifier, indexed starting from 0.

  • 1D Array (List): marks = [72, 85, 91, 64] → marks[2] returns 91 (the 3rd item).
  • 2D Array (Table / Grid): Accessed with two indices: grid[row][col] (e.g., a cinema seating plan or tic-tac-toe board).

2. Subroutines: Procedures vs. Functions

Subroutines are named, reusable blocks of code created during decomposition:

  • Procedure: Executes a sequence of statements without returning a value (e.g., displayMenu()).
  • Function: Executes a sequence of statements and returns a value (RETURN result) back to the calling line (e.g., area = calculateArea(5, 4)).
  • Parameters & Local Variables: Parameters pass data into a subroutine safely; local variables only exist inside that subroutine, preventing accidental side effects elsewhere in the program.

4. File Handling (Persistent Secondary Storage)

Variables in RAM vanish when a program ends. File handling reads/writes persistent external .txt or .csv files:

// Modes: "r" = Read, "w" = Write (overwrites file), "a" = Append (adds to end)
file = open("scores.txt", "r")
WHILE NOT file.endOfFile()
    record = file.readLine()
    OUTPUT record
ENDWHILE
file.close()  // Crucial: flushes buffer to disk and unlocks the file

5. SQL (Structured Query Language)

Used to query and filter records from relational database tables:

SELECT StudentName, Grade
FROM MockResults
WHERE Subject = 'Computer Science' AND Grade >= 7
ORDER BY Grade DESC;
  • SELECT * selects all columns in the table.
  • WHERE Name LIKE 'A%' uses the % wildcard to match any student whose name starts with `'A'`.
  • ORDER BY ... ASC / DESC sorts results ascending (A–Z / lowest-to-highest) or descending (Z–A / highest-to-lowest).

✅ Quick Coding & SQL Self-Test

Q1: What is the key difference between opening a file in "w" mode vs. "a" mode?

"w" (Write) erases all existing contents in the file before writing new data, whereas "a" (Append) preserves existing data and adds new lines at the very end.

Q2: In a 0-indexed 1D array days = ["Mon", "Tue", "Wed", "Thu", "Fri"], what does days[3] output?

"Thu" (because index 0 = Mon, index 1 = Tue, index 2 = Wed, index 3 = Thu).
