2.2.1
Data types
Every value in a program has a type that determines what you can do with it

A data type tells the computer what kind of value a variable holds and what operations are valid on it. Choosing the wrong type causes errors or unexpected results.

Integer
Whole numbers — positive, negative, or zero. No decimal point. Used for counting, loop counters, array indices.
-5   0   42   1000
Real / Float
Numbers with a decimal point. Used for measurements, prices, averages, and any result of division.
3.14   -0.5   99.9
Boolean
Can only be TRUE or FALSE. Used for conditions, flags, and logical decisions.
TRUE   FALSE
Character
A single character — letter, digit, or symbol. Stored as an ASCII/Unicode code internally.
'A'   '7'   '!'
String
A sequence of zero or more characters. Text data. Name, message, or any combination of characters.
"Hello"   "Year 11"

Choosing the right type

ScenarioData typeWhy
A student's ageIntegerAge is always a whole number
A student's nameStringNames are text — letters and spaces
Is the student present?BooleanOnly two possibilities: yes or no
A student's percentage scoreRealCould be 87.5 — needs a decimal point
First letter of surnameCharacterA single letter, not a full string
Exam tip
Exam questions often ask you to state the data type for a given scenario. Always justify your choice — saying "Integer because age is a whole number" scores higher than just "Integer".

2.2.2
Variables and constants
Named locations in memory that store values during a program's execution

Variables

A variable is a named memory location whose value can change during execution. Think of it as a labelled box — you can put something in, take it out, and replace it with something new.

pseudocode
// Assignment uses the ← operator
score ← 0               // score starts at 0
score ← score + 10      // score is now 10
name  ← "Alice"          // name holds a string
found ← FALSE           // found is a Boolean flag

Constants

A constant is a named value that is set once and never changes. Constants make code easier to read and maintain — change the value in one place and it updates everywhere it's used.

pseudocode
// Constants are often written in UPPER_CASE
CONST PI          ← 3.14159
CONST MAX_ATTEMPTS ← 3
CONST PASS_MARK    ← 40

// Now if the pass mark changes, update just one line:
IF score >= PASS_MARK THEN
    OUTPUT("Pass")
END IF
Variable
Value CAN change. Use for scores, counters, user input, running totals — anything that updates during the program.
Constant
Value CANNOT change. Use for fixed values like PI, tax rates, maximum attempts, screen dimensions.

Naming rules

  • Names must start with a letter — not a number or symbol
  • Names can contain letters, digits, and underscores: student_name, score2
  • Names cannot contain spaces — use camelCase (totalScore) or underscores (total_score)
  • Names should be meaningful — studentAge is better than x
  • Names are usually case-sensitive in real languages
Exam tip
A common exam question is "state ONE advantage of using a constant instead of a variable". Answer: if the value needs to change, you only need to update it in one place — reducing errors. Also: the name makes the code self-documenting.
🧠 Memory trick: A variable is like a whiteboard — you can erase and rewrite. A constant is like text carved in stone — it stays the same forever.

MOD vs DIV
17 DIV 5 = 3 (how many times 5 goes into 17 — the quotient). 17 MOD 5 = 2 (what's left over — the remainder). Together they give you both parts of the division: 17 = (5 × 3) + 2.

2.2.4
Selection (IF statements)
Making decisions — executing different code depending on conditions

Selection allows a program to branch — to execute different code depending on whether a condition evaluates to TRUE or FALSE. Without selection, programs could only run the same steps every time.

Simple IF...ELSE

pseudocode
IF score >= 50 THEN
    OUTPUT("Well done, you passed!")
ELSE
    OUTPUT("Sorry, you failed. Try again.")
END IF

IF...ELSE IF...ELSE (multiple branches)

pseudocode
IF score >= 70 THEN
    grade ← "A"       // 70 and above
ELSE IF score >= 55 THEN
    grade ← "B"       // 55 to 69
ELSE IF score >= 40 THEN
    grade ← "C"       // 40 to 54
ELSE
    grade ← "Fail"   // below 40
END IF
OUTPUT("Your grade: " + grade)

SWITCH / CASE statement

When selecting between many fixed values of the same variable, SWITCH is cleaner than a long IF...ELSE IF chain.

pseudocode
day ← INPUT("Enter day (1-7): ")
SWITCH day:
    CASE 1: OUTPUT("Monday")
    CASE 2: OUTPUT("Tuesday")
    CASE 3: OUTPUT("Wednesday")
    CASE 4: OUTPUT("Thursday")
    CASE 5: OUTPUT("Friday")
    DEFAULT: OUTPUT("Weekend")
END SWITCH

Common mistake
Always check conditions from highest to lowest (or lowest to highest consistently). If you check score ≥ 40 first, then everyone with 70+ also satisfies that — they'd all get "C" instead of "A"!
Exam tip
Always include END IF to close your selection block. Forgetting it is the most common pseudocode error in exams.
2.2.5
Iteration (loops)
Repeating blocks of code — the most powerful tool in programming

Iteration allows a block of code to be executed multiple times without rewriting it. There are two main types: count-controlled (FOR) and condition-controlled (WHILE / DO...UNTIL).

FOR loop — count-controlled

Use when you know exactly how many times the loop should run before it starts.

pseudocode
// Print the 5 times table
FOR i ← 1 TO 10
    OUTPUT(i * 5)
END FOR
// Outputs: 5, 10, 15, 20, 25, 30, 35, 40, 45, 50

WHILE loop — pre-condition

Checks the condition BEFORE each iteration. May never run if condition is false from the start.

pseudocode
total ← 0
WHILE total < 100
    n ← INPUT("Enter a number: ")
    total ← total + n
END WHILE
OUTPUT("Total reached: " + total)

DO...UNTIL — post-condition

Checks condition AFTER each iteration. Always runs at least once — perfect for input validation.

pseudocode
DO
    age ← INPUT("Enter your age (0–120): ")
UNTIL age >= 0 AND age <= 120
OUTPUT("Valid age entered: " + age)

WHILE vs DO...UNTIL
WHILE: condition checked first — may run 0 times.
DO...UNTIL: condition checked last — always runs at least once.
When to use each
FOR: you know the count. WHILE: unknown count, check before. DO...UNTIL: must run at least once (e.g. input validation).
Exam tip — most tested loop question
"Explain the difference between a WHILE loop and a DO...UNTIL loop." WHILE checks condition before — may never execute. DO...UNTIL checks after — always executes at least once. This difference earns 2 marks every time it appears.

String indexing

Each character in a string has an index number. In most GCSE pseudocode, indexing starts at 0 (the first character is at position 0).

example
word ← "Python"
// Index:   0  1  2  3  4  5
//          P  y  t  h  o  n
SUBSTRING(word, 0, 1)  // → "P"  (1 char from index 0)
SUBSTRING(word, 0, 3)  // → "Pyt" (3 chars from index 0)
LEN(word)               // → 6

Worked example — count vowels

pseudocode
word  ← INPUT("Enter a word: ")
count ← 0
FOR i ← 0 TO LEN(word) - 1
    letter ← SUBSTRING(LOWER(word), i, 1)
    IF letter = "a" OR letter = "e" OR letter = "i"
    OR  letter = "o" OR letter = "u" THEN
        count ← count + 1
    END IF
END FOR
OUTPUT(word + " contains " + STR(count) + " vowels")

ASC and CHR
ASC("A") = 65, ASC("a") = 97. The difference between upper and lower case ASCII values is always 32. CHR(65) = "A". These come up in cipher/encryption questions — e.g. shifting letters by adding to their ASCII value.
2.2.7
Arrays
Storing multiple values of the same type under one variable name

An array stores multiple values in a single named structure. Each value is accessed using an index number. Arrays make it much easier to work with lists of data — without them you'd need a separate variable for every value.

1D arrays (single-dimensional)

pseudocode
// Declare and initialise a 1D array
scores ← [85, 72, 91, 64, 78]

// Access individual elements by index (starts at 0)
OUTPUT(scores[0])    // → 85  (first element)
OUTPUT(scores[4])    // → 78  (last element)

// Modify an element
scores[2] ← 95       // changes 91 to 95

// Traverse ALL elements using a FOR loop
FOR i ← 0 TO LENGTH(scores) - 1
    OUTPUT(scores[i])
END FOR

2D arrays (grids / tables)

pseudocode
// A 3x3 2D array — like a grid
grid ← [[1,2,3],[4,5,6],[7,8,9]]

// Access: grid[ROW][COLUMN]
OUTPUT(grid[0][0])   // → 1  (row 0, col 0)
OUTPUT(grid[1][2])   // → 6  (row 1, col 2)
OUTPUT(grid[2][1])   // → 8  (row 2, col 1)

// Traverse with nested loops
FOR row ← 0 TO 2
    FOR col ← 0 TO 2
        OUTPUT(grid[row][col])
    END FOR
END FOR

Common array algorithms

Find maximum
max ← list[0]
FOR i ← 1 TO LEN-1
  IF list[i] > max
    max ← list[i]
OUTPUT max
Calculate total
total ← 0
FOR i ← 0 TO LEN-1
  total ← total + list[i]
average ← total / LEN
OUTPUT average
Exam tip — 2D arrays
Remember array[ROW][COLUMN] — row first, column second. Think of it like coordinates on a spreadsheet: row = which row down, column = which column across.
2.2.8
File handling
Reading and writing data that persists between program runs

Variables lose their values when a program ends. File handling allows programs to save data permanently to secondary storage and read it back again. This is how real applications (games, databases, apps) remember information between sessions.

Why file handling matters

  • Without files: scores, settings, and records are lost when the program closes
  • With files: data persists — a game remembers your high score, a database keeps records
  • Files are stored on secondary storage (HDD, SSD) — non-volatile memory

Writing to a file

pseudocode
// Open file in write mode (creates or overwrites)
OPEN("scores.txt", "write")
WRITELINE("scores.txt", "Alice: 85")
WRITELINE("scores.txt", "Bob: 72")
WRITELINE("scores.txt", "Carol: 91")
CLOSE("scores.txt")    // ALWAYS close files when done

Reading from a file

pseudocode
OPEN("scores.txt", "read")
WHILE NOT EOF("scores.txt")    // EOF = End Of File
    line ← READLINE("scores.txt")
    OUTPUT(line)
END WHILE
CLOSE("scores.txt")

Appending to a file

pseudocode
// Append mode adds to the end without overwriting
OPEN("scores.txt", "append")
WRITELINE("scores.txt", "Dave: 78")
CLOSE("scores.txt")

The three file modes

ModeEffectUse case
"read"Opens for reading only. File must exist.Loading saved data, reading a config
"write"Creates new file or overwrites existing content entirely.Saving a new record, overwriting old data
"append"Opens existing file and adds to the end without deleting.Adding a new log entry, adding a new score
Critical rule
Always CLOSE a file after you have finished with it. An unclosed file can become corrupted, and other programs may not be able to access it. Every OPEN must have a matching CLOSE.
EOF explained
EOF (End Of File) is a signal that the program has reached the last line of the file. The WHILE NOT EOF loop keeps reading until there are no more lines to read — this works for files of any length.
🧠 File handling analogy: Opening a file is like taking a book off a shelf. Reading is like turning the pages. Writing is like filling in a notebook. CLOSE is like putting the book back — you must always do it or you'll lose your place (or the whole book).
2.2.9
Sub-programs
Procedures and functions — the building blocks of modular programs

A sub-program is a named block of code that performs a specific task and can be called from multiple places in a program. They are the foundation of modular programming — breaking a program into reusable, self-contained parts.

Why use sub-programs?

  • Reusability — write once, call many times. No duplicate code
  • Readability — the main program reads like a list of tasks: greetUser(), getScore(), saveResult()
  • Easier testing — test each sub-program individually before combining
  • Team development — different programmers can work on different sub-programs simultaneously
  • Maintainability — fix a bug in one sub-program and it's fixed everywhere it's called

Procedures — no return value

A procedure performs a task but does NOT send a value back. It is called by name.

pseudocode
// Define the procedure
PROCEDURE greet(name)
    OUTPUT("Hello, " + name + "! Welcome to the quiz.")
END PROCEDURE

// Call the procedure — it runs the code inside
greet("Alice")    // → Hello, Alice! Welcome to the quiz.
greet("Bob")      // → Hello, Bob! Welcome to the quiz.

Functions — return a value

A function performs a task AND sends a value back using RETURN. The result can be stored in a variable or used in an expression.

pseudocode
// Define the function
FUNCTION calculateArea(width, height)
    area ← width * height
    RETURN area
END FUNCTION

// Call the function — store the returned value
roomArea ← calculateArea(5, 8)    // roomArea = 40
OUTPUT("Room area: " + STR(roomArea) + " m²")

Key terminology

Parameters & Arguments
FUNCTION add(a, b)   ← a and b are PARAMETERS (in definition)   result ← add(5, 3)  ← 5 and 3 are ARGUMENTS (in the call)
Local vs Global
LOCAL: declared inside a sub-program. Only accessible there. Destroyed when sub-program ends.   GLOBAL: declared outside all sub-programs. Accessible everywhere.
scope example
total ← 0          // GLOBAL — accessible everywhere

FUNCTION addTen(x)
    result ← x + 10   // LOCAL — only exists inside addTen
    RETURN result
END FUNCTION

total ← addTen(5)   // total = 15
// OUTPUT(result)    ← ERROR! result is local — doesn't exist here
Exam tip — procedure vs function
The key difference: a function RETURNS a value using RETURN; a procedure does NOT. If asked "what is the difference between a procedure and a function?" — this one distinction earns both marks.
Best practice — prefer local variables
Use local variables wherever possible. Global variables can be changed by any part of the program, making bugs hard to trace. Local variables are safer, more predictable, and easier to debug.
