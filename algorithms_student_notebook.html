2.1.1
Computational Thinking
How to approach problems like a computer scientist

Computational thinking is a way of solving problems by breaking them down into steps a computer can follow. It has three key pillars.

The three pillars

Decomposition
Breaking a big problem into smaller sub-problems that are easier to solve individually.
Abstraction
Removing unnecessary detail — focusing only on what matters for the solution.
Algorithmic thinking
Defining a clear, step-by-step set of rules (an algorithm) that solves the problem.
Pattern recognition
Spotting similarities and patterns between problems so you can reuse existing solutions.

Real-world example — building a game

Imagine you have to build a quiz app. Use computational thinking to plan it:

  • Decompose: Load questions → Display question → Get user answer → Check answer → Show score → Repeat
  • Abstract: Ignore how the screen looks for now. Focus on the logic.
  • Algorithm: Write out each step as instructions the computer can follow.
  • Pattern: "Check answer" works the same for every question — write it once, reuse it.

🧠 Memory trick: Think of planning a birthday party.
Decompose = write the to-do list (venue, cake, guests…)
Abstract = ignore the colour of the tablecloth (not important!)
Algorithm = write the steps in the right order

What makes a good algorithm?

  • Unambiguous — every step has one clear meaning
  • Finite — it must eventually stop (not loop forever)
  • Correct — it produces the right output for all valid inputs
  • Efficient — it uses as little time and memory as possible
Key definition — Algorithm
A finite set of unambiguous, step-by-step instructions that solves a problem or achieves a goal. Every program you write IS an algorithm.
2.1.2
Pseudocode
Writing algorithms in structured English — no strict syntax needed

Pseudocode lets you plan your algorithm without worrying about a specific programming language. It uses English-like commands with a clear, consistent structure.

Core constructs

1. Variables and input/output

pseudocode 
// Store a value in a variable using ←
name ← "Alice"
score ← 0
age ← INPUT("Enter your age: ")

// Display output
OUTPUT("Hello, " + name)
OUTPUT("Score: " + STR(score))

2. Selection (IF statements)

pseudocode 
IF score >= 70 THEN
    OUTPUT("Distinction")
ELSE IF score >= 50 THEN
    OUTPUT("Pass")
ELSE
    OUTPUT("Fail")
END IF

3. Iteration — FOR loop (count-controlled)

pseudocode 
// Runs exactly 5 times
FOR i ← 1 TO 5
    OUTPUT(i * 2)
END FOR
// Outputs: 2, 4, 6, 8, 10

4. Iteration — WHILE loop (condition-controlled)

pseudocode 
password ← ""
WHILE password ≠ "letmein"
    password ← INPUT("Enter password: ")
END WHILE
OUTPUT("Access granted!")

5. DO...UNTIL (always runs at least once)

pseudocode 
DO
    number ← INPUT("Enter a positive number: ")
UNTIL number > 0
WHILE vs DO...UNTIL
WHILE checks the condition BEFORE running — it might run 0 times. DO...UNTIL checks AFTER — it always runs at least once. This is a very common exam question!

Flowcharts
Representing algorithms visually with standard symbols

A flowchart represents an algorithm as a diagram using standardised shapes connected by arrows. Each shape has a specific meaning — you must use the correct shape or lose marks.

The five symbols you must know

Terminal (oval / rounded rectangle)
Used ONLY at the very beginning (START) and very end (STOP/END) of the algorithm. Every flowchart must have exactly one of each.
Process (rectangle)
An action, calculation, or assignment. e.g. "total ← total + score" or "Set count to 0". The most common shape in a flowchart.
Decision (diamond)
A YES/NO question that branches the flow. Always label both exits — one arrow for YES, one for NO. e.g. "Is score ≥ 70?"
Input / Output (parallelogram)
Data coming IN from the user (keyboard) or going OUT to the screen. e.g. "INPUT name" or "OUTPUT result". Label it clearly.
Flow arrow
Shows the direction of flow between shapes. Arrows must be labelled where they come from a decision diamond (YES / NO).

Using rectangles for decisions (must be diamond). Not labelling YES/NO on branches. Forgetting START and STOP terminals. Arrows pointing the wrong way — always show direction!

Searching Algorithms
Linear search and binary search — with live demos
Linear search
  • Works on any list (sorted or unsorted)
  • Checks each item one by one from the start
  • Simple to write and understand
  • Slow for large lists — worst case: checks every item
  • Time complexity: O(n)
Binary search
  • List MUST be sorted first
  • Halves the search space each step
  • Much faster for large lists
  • More complex to implement
  • Time complexity: O(log n)

Pseudocode — binary search

pseudocode 
FUNCTION binarySearch(list, target)
    low  ← 0
    high ← LENGTH(list) - 1
    WHILE low <= high
        mid ← (low + high) DIV 2
        IF list[mid] = target THEN
            RETURN mid          // Found!
        ELSE IF list[mid] < target THEN
            low ← mid + 1    // Target is in right half
        ELSE
            high ← mid - 1   // Target is in left half
        END IF
    END WHILE
    RETURN -1               // Not found
END FUNCTION
Why is binary search faster?
A list of 1,000 items: linear search may check all 1,000. Binary search takes at most log₂(1000) ≈ 10 comparisons. For 1 million items: linear = 1,000,000 checks; binary = only 20 checks!

Bubble sort

Compares adjacent pairs and swaps if they're in the wrong order. Each full pass "bubbles" the largest remaining value to the end.

pseudocode 
PROCEDURE bubbleSort(list)
    n ← LENGTH(list)
    FOR pass ← 1 TO n - 1
        FOR i ← 0 TO n - pass - 1
            IF list[i] > list[i+1] THEN
                // Swap
                temp ← list[i]
                list[i] ← list[i+1]
                list[i+1] ← temp
            END IF
        END FOR
    END FOR
END PROCEDURE
Optimisation tip
If no swaps happen during a full pass, the list is already sorted — stop early! Add a "swapped" flag and break out of the loop. This gives O(n) best case instead of always doing n-1 passes.

Merge sort

Divide and conquer. Split the list in half repeatedly until every sub-list has 1 element, then merge pairs back together in sorted order.

  • Phase 1 — Divide: Keep halving until all sub-lists have 1 item (1 item is always "sorted")
  • Phase 2 — Merge: Compare the fronts of two sub-lists, take the smaller, repeat until merged
  • Efficiency: O(n log n) always — much better than bubble sort for large data
  • Downside: Needs extra memory to hold the sub-lists during merging

Insertion sort

Builds a sorted section one item at a time. Takes each new item and inserts it into its correct position in the already-sorted section.

  • Great for small lists or lists that are already nearly sorted
  • Best case O(n) — already sorted means no moves needed
  • Worst case O(n²) — reverse-sorted list means maximum moves

Trace Tables
Manually stepping through algorithms to track variable values

A trace table records the value of every variable at each step of an algorithm. It is essential for debugging and a very common exam question type.

The golden rule of trace tables
Create one column for EACH variable AND a column for OUTPUT. Work through every single step — never skip. Partial marks are awarded for correct intermediate values even if your final answer is wrong.

How to build a trace table

  • Step 1: Identify every variable in the algorithm
  • Step 2: Create a column for each variable plus an OUTPUT column
  • Step 3: Read through the algorithm line by line
  • Step 4: Fill in the new value each time a variable changes
  • Step 5: Leave a cell blank if a variable doesn't change on that step

Section A — Short answers

1. Define the term "algorithm". [2 marks]
A finite (1) set of step-by-step instructions (1) that solve a problem or achieve a specific goal (1). Award up to 2 marks. Key words: finite, unambiguous, step-by-step.
2. State TWO differences between a linear search and a binary search. [2 marks]
Any two of: Binary search requires the list to be sorted first; linear search does not (1). Binary search is more efficient / faster for large lists (1). Linear search checks items one at a time; binary search repeatedly halves the search space (1). Binary search has O(log n) complexity; linear has O(n) (1).
3. A list contains the values: [3, 7, 12, 19, 25, 31, 44]. A binary search is used to find the value 19. Show the steps. [3 marks]
Step 1: low=0, high=6, mid=3 → list[3]=19. Found at index 3 (1 mark). OR: Step 1: mid=(0+6)÷2=3 (1). list[3]=19 = target (1). Found in 1 comparison (1). Award marks for correct mid calculation, correct comparison, and identifying the item as found.
4. Trace the following algorithm for the list [5, 2, 8, 1]. Show the state of the list after EACH pass of bubble sort. [3 marks]
Start: [5, 2, 8, 1]
Pass 1: Compare 5,2 → swap → [2,5,8,1]. Compare 5,8 → no swap. Compare 8,1 → swap → [2,5,1,8] (1 mark)
Pass 2: Compare 2,5 → no swap. Compare 5,1 → swap → [2,1,5,8] (1 mark)
Pass 3: Compare 2,1 → swap → [1,2,5,8] (1 mark). Sorted!

Section B — Extended questions

5. Explain what is meant by "decomposition" in computational thinking and give ONE example of how it could be used when designing a school library system. [3 marks]
Decomposition means breaking a large/complex problem (1) into smaller, more manageable sub-problems (1). For a library system, this could mean breaking it down into: searching for a book, borrowing a book, returning a book, managing member accounts, and generating overdue notices (1 — award for any sensible, specific sub-problem).
6. Write pseudocode for a program that asks the user to enter numbers one at a time, adds them to a running total, and stops when the user enters 0. It should then output the total. [4 marks]
total ← 0 (1)
number ← INPUT("Enter a number (0 to stop): ") (1)
WHILE number ≠ 0 (1)
   total ← total + number
   number ← INPUT("Enter a number (0 to stop): ")
END WHILE
OUTPUT total (1)

Mark scheme: 1 for initialising total; 1 for correct input; 1 for correct WHILE condition; 1 for output after loop. Accept DO...UNTIL equivalent.
7. Compare the efficiency of bubble sort and merge sort. Which would you recommend for sorting a list of 10,000 student names, and why? [4 marks]
Bubble sort has O(n²) worst case — for 10,000 items this could mean ~100 million comparisons (1). Merge sort has O(n log n) always — for 10,000 items this is ~130,000 comparisons (1). Merge sort is significantly faster for large datasets (1). I would recommend merge sort (1) because the list is large (10,000 items) and merge sort's consistent O(n log n) performance would be much faster than bubble sort's O(n²), despite requiring more memory (accept any well-reasoned answer).
